# 品牌与命名规范

本文定义 ComfyUI-WorkspaceKit 的对外品牌、中文称呼和模块命名规则。它约束文档、视频、截图、语言文案和未来关联插件的呈现；**不改变**现有插件目录、Python 包、JavaScript Provider ID、接口名、存储键或 Registry 标识。

## 1. 名称层级

| 层级 | 标准写法 | 使用位置 |
| --- | --- | --- |
| 正式英文产品名 | **ComfyUI WorkspaceKit** | GitHub、Registry、安装说明、首次介绍 |
| 技术仓库/插件名 | **ComfyUI-WorkspaceKit** | 仓库、目录、安装命令、技术引用 |
| 对外简称 | **WK** | Logo、视频章节、模块前缀；首次出现后才使用 |
| 系列称呼 | **WK 套件** | 介绍 WorkspaceKit 与关联模块的整体能力 |
| 中文正式名 | **WK 工作区** | 中文 README、关于页面、社区介绍 |
| 解释性定位 | **面向重度 ComfyUI 用户的创作工作台** | 副标题、简介、宣传文案 |

首次对外介绍使用：

> **ComfyUI WorkspaceKit（WK）**，中文称为 **WK 工作区**，是一个面向重度 ComfyUI 用户的创作工作台。

之后可在同一篇文档、同一支视频或同一页界面中简称为 `WK`。`WK` 本身搜索辨识度较低，因此不应替代 GitHub、Registry、安装说明中的完整名称。

## 2. 模块命名

文档、视频、更新说明和社区交流中，统一使用下列模块名称：

| 模块 | 对外名称 | 界面内的简短标签 |
| --- | --- | --- |
| 工作流管理 | **WK 工作流** | 工作流 |
| 节点管理 | **WK 节点** | 节点 |
| 模板管理 | **WK 模板** | 模板 |
| 画布编组 | **WK 编组** | 编组 |
| 排版工具 | **WK 版式** / **版式面板** | 版式 |
| 主题工具 | **WK 主题** / **主题面板** | 主题 |

`WK 版式` 和 `WK 主题` 是 WK 套件的关联模块；其独立仓库和安装说明仍保留完整英文技术名，例如 `ComfyUI-WorkspaceKit-Layout`。

进入 WorkspaceKit 后，顶部标签和操作按钮不需要重复添加 `WK` 前缀，例如使用“工作流｜节点｜模板｜版式｜主题”，右键操作使用“编组”。这能保持界面简洁，同时在外部传播中维持统一的模块名称。

## 3. 用词边界

- **工作区**：中文正式产品名，适合稳定、正式的文档场景。
- **WK 套件**：系列总称，适合介绍 WorkspaceKit、Layout、Theme 及未来关联插件。
- **效率面板**：可作为传播性描述，例如“ComfyUI 的效率面板”；不作为唯一正式产品名，因为 WK 不只是一块面板。
- **创作工作台**：产品定位语，用来帮助新用户理解功能范围；不代替正式产品名。
- **面板**：可用于 UI 描述，例如“版式面板”；不写入内部接口、数据字段或模块 ID，以避免限制未来的呈现方式。

## 4. 一致性规则

1. 不混用 `WK`、`WS`、`CWK` 等多个简称；统一使用 `WK`。
2. 不使用 `ComfyKit`、`ComfyKit 工作台` 等名称。该名称已被其他 ComfyUI 相关项目使用，容易造成搜索和品牌混淆。
3. 新的关联插件优先采用 `ComfyUI-WorkspaceKit-<Module>` 的技术命名，并在对外文案中使用 `WK <模块>`。
4. 品牌文案的改动不得顺带改动已有安装路径、Registry 名称、Provider API、缓存/存储键或工作流数据格式。任何技术标识变更必须单独评估兼容性与迁移路径。

## 5. 后续落地顺序

1. 更新 README、Registry 简介、截图标题和视频章节中的对外称呼。
2. 审核中英文语言包中用户可见的产品与模块文案。
3. 为 Layout、Theme 和未来模块补充同一套品牌说明。
4. 最后再评估 Logo、Banner、图标和视觉资产；这些不应阻塞功能开发。
