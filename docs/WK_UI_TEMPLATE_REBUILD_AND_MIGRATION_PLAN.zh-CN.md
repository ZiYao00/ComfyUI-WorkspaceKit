# WK UI Template 重建与迁移计划

> 状态：**进行中：Batch 0、1 与其 Vendor 同步、Layout 验收，以及 Theme 四槽骨架首批已完成；Theme 业务功能迁移尚未开始。**  
> 更新：2026-08-02  
> 范围：`ComfyUI-WorkspaceKit`、`ComfyUI-WorkspaceKit-Layout`、`ComfyUI-WorkspaceKit-Theme`

## 1. 目标与结论

WK 套件已经有一套 Panel UI Template v1：`entry/ui-kit/` 是唯一可编辑源，Layout 与 Theme 通过生成的 Vendor 副本独立运行，并在安装兼容 WK 时使用宿主运行时 Template。

本计划不新建第二套 UI 系统，也不直接删除当前 Template。目标是以当前公开接口为兼容基线，按新的家族规范重建其实现，并由 Layout、Theme 的真实运行结果验收。

最终结果必须同时满足：

- WK、Layout、Theme 使用同一套面板骨架、间距、边框和控件节奏；
- Layout 与 Theme 在合并及独立模式下保持同一视觉语言；
- 不破坏现有 Provider 注册、侧边栏生命周期、独立 Vendor 回退与已安装用户；
- Theme 的新功能只建立在已经验收的 Template 之上；
- 图标系统统一改造由独立的 [WK 图标系统计划](WK_ICON_SYSTEM_PLAN.zh-CN.md) 跟进，不与 Template 或 Theme 功能批次混做。

## 3. 四层实施模型

### 第一层：先定规则

明确 Template 的责任、五分区、可复用原语、Token、版本能力和 Vendor 同步规则。此层不改 Layout、Theme 业务功能。

### 第二层：验收规则

使用 Layout 与 Theme 现有功能验证合并、独立、Vendor 回退和主题外观矩阵。发现问题时先定位到 Template、Vendor、Provider、模块 CSS 或业务层，禁止直接在业务模块盲补。

### 第三层：Theme 骨架迁移

仅迁移 Theme 的信息架构：将标题/状态、主题来源、搜索、动作条、参考图与内容区放入正确 Blueprint 区域。保留原有主题值、保存、导入和取色行为。

### 第四层：Theme 新功能

在骨架验收通过后，分批实现主题选择菜单、统一动作体系、自动 ID、参考图色板、背景上传与预设等功能。每项功能独立验证，不与 Template 重建混做。

## 4. 家族 UI 骨架规范（目标）

所有 WK 家族面板使用固定的垂直顺序：

```text
Tab strip（WK 宿主或独立壳层）
Header（标题 + 简短状态）
Toolbar（搜索或上下文编辑信息）
Controls（模式、滑块、常用动作）
Content（可滚动功能内容）
```

规则：

- 空的 Toolbar 或 Controls 必须隐藏，不得留下空白占位；
- 一级分区使用低对比 1px 边框和固定留白，不使用重色块作为唯一分隔；
- 分区内部不得同时叠加横线、折叠线、卡片粗边框等同等级边界；
- 窄宽度优先保留主操作，次要操作进入统一更多菜单，不允许破坏为多行错位按钮；
- 透明与磨砂模式只调整 Token 的不透明度与对比度，不改变 DOM 分区结构。

## 5. 计划补齐的通用原语

这些是 Template 能力，不包含具体业务逻辑：

| 原语 | Template 负责 | 模块仍负责 |
| --- | --- | --- |
| `createDisclosureSection()` | 折叠状态、标题、数量、弱边界、键盘/无障碍外观 | 分区内容与业务筛选 |
| `createCompactActionBar()` | 图标按钮、更多菜单、禁用/溢出、窄宽度节奏 | 命令语义、启用条件与执行 |
| `createDropzoneSurface()` | 空/悬停/已选择状态的统一表面 | 文件格式、读取、压缩、存储和错误处理 |
| 分区与边框 Token | 间距、边框、焦点、浅色/深色/透明/磨砂适配 | 功能专属颜色与卡片布局 |

新增能力为 Template v1 的可选 capability，不随意更改已发布的 Provider API、现有方法名、类名或 Vendor 清单。若发生不兼容变更，必须先提供 v1 兼容适配层。

| 5 | Theme 来源选择与统一动作命令 | Theme | Template 私有实现 | 图标栏和菜单调用同一命令 |

## 8. Theme 后续功能边界

Theme 骨架通过后才进入以下专项；这些不是 Template 的职责：

1. 自定义主题选择菜单：内置/WK 主题列表，以及“读取当前界面”命令；
2. 统一动作命令：导入、保存、另存为、导出 JSON、还原载入值、退出编辑；
3. 自动 ID：首次保存基于文件名生成、已保存主题保持稳定、另存为生成新 ID；
4. 参考图：点击/拖放导入、缩略图替换、清除、稳定的推荐色板；
5. 参数区：紧凑字段布局、色块无冗余外框、复杂 CSS 阴影保留高级模式；
6. 背景图：预设资源 manifest 与自定义上传分开处理。

### 背景图的硬约束

当前 Theme 保存服务有主题 JSON 体积限制。3 MB 图片直接转 Base64 后约为 4 MB，不能直接保存。背景图方案必须在实现前单独确认：

- 用户选择的原图上限；
- 浏览器本地压缩后的嵌入上限；
- 透明图片的格式策略；
- 预设背景使用资源 ID，而不是绝对磁盘路径或重复 Base64；
- 超限时不覆盖当前编辑会话。

## 9. 备份、回退与发布规则

- 每次涉及 Template、Vendor 或多个仓库前，分别在受影响项目的 `.codex-backups/` 创建源码压缩备份；
- Vendor 只可由导出工具更新，禁止手工修改；
- 未通过验收的 Template 不进入 Layout/Theme 发布；
- 未经用户明确要求，不提交、推送或创建 Release；
- 本计划完成前，旧 Template 作为只读兼容基线保留；新实现通过矩阵后才归档旧实现。
